# redrive — plan

## Context

**Who and why.** The maintainer is building redrive for other people: office workers who take notes in Microsoft OneNote during the day, own a reMarkable tablet (developer mode on, so root SSH is available), and do not want to pay for reMarkable Connect just to move documents back and forth. The tablet should hold the day's OneNote pages by the evening; whatever they write on the tablet at night should be waiting in OneNote the next morning.

**Constraints that shape everything.**
- No tablet on hand during development. Everything is built against a local "fake tablet" (SSH server + sample data + mock web interface) and then verified with a short field-test checklist on the first real device.
- The tablet's storage is not a file tree. `/home/root/.local/share/remarkable/xochitl/` is a flat directory of UUID-named files; folder structure and titles live inside `{uuid}.metadata` JSON. A raw mount shows UUIDs.
- The tablet auto-sleeps after idle and its USB networking drops during sleep. Any live connection dies regularly; the design must be opportunistic, not persistent.
- Windows targets are ordinary office PCs: stock Windows 10/11, PowerShell 5.1, built-in OpenSSH client. Users can install software once (admin prompt) but otherwise run as a normal user.

**Decisions already made (with the maintainer, 2026-09-01, re-confirmed after a second pass).**
| Decision | Choice |
|---|---|
| Core shape | **Synced copy shown as a drive.** Windows keeps a local mirror folder with real names, exposed as a drive letter; a background agent copies changes both ways whenever the tablet is plugged in. A raw SSHFS/rclone mount of the xochitl directory stays available as an optional power-user/troubleshooting tool. |
| Stack | PowerShell 5.1 scripts, zero installs for the core. Compile/rewrite later only if needed. |
| OneNote bridge | Page-level, two-way: each OneNote page → one PDF on the tablet under `OneNote/<Notebook>/<Section>`; tablet handwriting → appended to the source OneNote page as images plus attached PDF; native tablet notebooks → pages in a "From reMarkable" section. |
| Transport | **USB cable only.** Fixed address 10.11.99.1; the tablet's official USB web interface (http://10.11.99.1) is directly reachable; SSH over the same link for everything the web interface cannot do. |

**How those combine.** One connection core (SSH + web interface over USB) feeds two consumers: the **mirror engine** that maintains the drive folder, and the **OneNote bridge** that reads and writes that same folder plus OneNote. Nothing user-facing depends on a live link: the drive is a normal NTFS folder; sync happens opportunistically while the tablet is docked and awake.

**Options considered and why they lost.**
| Option | Verdict |
|---|---|
| Live SSHFS-Win mount of the raw xochitl folder | Shows UUID filenames; stale and Explorer-hanging whenever the tablet sleeps (well documented for SSHFS-Win and rclone mounts); SSHFS-Win's last binary is from 2020. Kept only as an opt-in troubleshooting tool. |
| Custom WinFsp virtual drive that translates UUIDs live | Most code of all options, still dead while the tablet sleeps, and rendering/OneNote would need a sync layer anyway. |
| reMarkable cloud replacement (rmfakecloud) | Needs hosts-file and CA hacks on the tablet that break on every OS update; a server to run; overkill. |
| Free OneDrive/Google Drive integration on the tablet | Free in 2026, but manual: the user browses and taps per file on the tablet, no automation, no OneNote awareness. |
| RCU (paid desktop utility) | Excellent manual tool over SSH; no scheduled sync, no OneNote; $12 per user. Good reference for fidelity. |
| **Synced local folder shown as a drive (chosen)** | Always available, sleep-tolerant, real names, tablet renders the handwriting for us, OneNote bridge is just files in a folder. |

## Verified on a stock Windows 11 PC (2026-09-01)
| Item | State |
|---|---|
| PowerShell | 5.1; Pester 3.4.0 ships with Windows (tests use Pester 5, a developer-only install) |
| OpenSSH client | 9.5p2 in `C:\Windows\System32\OpenSSH` (ssh, scp, sftp) — supports `StrictHostKeyChecking=accept-new`; `tar.exe` also ships with Windows |
| WinFsp / SSHFS-Win / rclone | winget ids `WinFsp.WinFsp`, `SSHFS-Win.SSHFS-Win` (binary unchanged since Dec 2020), `Rclone.Rclone` — only needed for the optional raw mount; rclone confirmed working against the tablet's Dropbear with `--sftp-host-key-algorithms ssh-ed25519` |
| OneNote | desktop OneNote (Microsoft 365 Click-to-Run, x64) with `OneNote.Application` COM registered; 64-bit PowerShell matches, so no COM bitness workaround needed |
| PDF rasterizing | WinRT `Windows.Data.Pdf.PdfDocument` **proven** from PowerShell 5.1 (AsTask reflection pattern): 2-page PDF loaded in 83 ms, page rendered at 150 dpi to PNG in memory in 282 ms (~320 KB) — zero installs |

## Goals and non-goals
**Goals.** One-time setup by a non-technical user (paste the tablet's SSH password once). A drive letter that is always there and fills itself in. A Doctor that says what is wrong and how to fix it. OneNote pages on the tablet by evening; handwriting back in OneNote by morning. Concise docs.

**Non-goals for v1.** Editing tablet documents in place from Windows; propagating Windows-side deletions to the tablet (too dangerous without confirmation UI); Wi-Fi; phones; the reMarkable cloud; rendering annotations on the PC (the tablet renders them for us).

## Architecture

```
 Windows PC (user session, non-elevated)                         reMarkable (USB, 10.11.99.1)
 ┌────────────────────────────────────────────────────┐          ┌──────────────────────────────┐
 │ redrive tray app (PowerShell, hidden window)       │  ssh/scp │ dropbear sshd (root, key)    │
 │  ├─ Watchdog: probe 10.11.99.1:22 every 10 s       │◄────────►│ /home/root/.local/share/     │
 │  ├─ Mirror engine: pull index → render → local tree│  http    │   remarkable/xochitl/*.{meta…}│
 │  │                 push new local files            │◄────────►│ xochitl web interface :80    │
 │  ├─ OneNote bridge: export changed pages → push    │          │   /documents /upload         │
 │  │                  harvest handwriting → OneNote  │          │   /download/{uuid}/pdf       │
 │  └─ Drive letter: subst R: → %USERPROFILE%\reMarkable        └──────────────────────────────┘
 └────────────────────────────────────────────────────┘
        │ COM (OneNote.Application)          │ state, logs: %LOCALAPPDATA%\redrive
        ▼                                     ▼
   OneNote desktop (must be running)     state.json, onenote-state.json, redrive.log
```

### 1. Connection core (`src/Connection.ps1`)
- **Native wrapper**: every external program (`ssh`, `scp`, `sftp`, `curl`, `subst`, `ssh-keygen`) runs through one `Invoke-RedriveNative` built on `System.Diagnostics.Process` with both streams read asynchronously, UTF-8 encodings, a timeout that kills the process, a raw argument string built by `ConvertTo-RedriveArgument` (PowerShell 5.1 mangles empty and quoted arguments), and success judged by exit code only (ssh writes warnings to stderr even on success, and `2>&1` turns those into terminating `NativeCommandError`s). Unit tests mock this single function.
- **Reachability**: `Test-RedriveDevice` = an `Up` interface holding an IPv4 in 10.11.99.0/24 (match by address, never by adapter name: RNDIS vs NCM naming differs across Windows builds; no address → no network probe at all) + `System.Net.Sockets.TcpClient.BeginConnect` to 10.11.99.1:22 with a 1.5 s cap. Distinguishes *unplugged* (no address) from *asleep* (address up, port closed) so the tray can say "tap the tablet to wake it". Key auth is verified only on the transition to connected; "Permission denied (publickey)" → NeedsSetup.
- **SSH**: `Invoke-RedriveSsh -Command -TimeoutSec` wraps `ssh.exe` with `-F <redrive ssh_config> remarkable`, `BatchMode=yes`, `ConnectTimeout=5`, `ServerAliveInterval=10`, `ServerAliveCountMax=3`. Output captured with `[Console]::OutputEncoding = UTF8`. Remote scripts longer than one line are shipped base64-encoded (`echo <b64> | base64 -d | sh`, BusyBox has `base64 -d`) to sidestep Windows quoting. The tablet's login shell is BusyBox `sh`: no GNU-only flags (`head -n N`, `sed -n 1,25p`, `stat -c`, no `find -printf`). Windows OpenSSH has no ControlMaster, so each call is a fresh connection (~0.3 s over USB; acceptable). All device traffic (SSH and HTTP) is serialized through one queue.
- **Files**: `Copy-RedriveToDevice` / `Copy-RedriveFromDevice` via `scp.exe -F <cfg>`, adding `-O` (legacy scp protocol) when the client is OpenSSH 9 or newer (Windows 11), because newer scp defaults to SFTP and the tablet's Dropbear may have no SFTP server; Windows 10's OpenSSH 8.1 scp is legacy already and has no `-O`. If Setup found an `sftp-server`, bulk copies use one `sftp.exe -b -` session with the batch on stdin instead. Bulk index via one `ssh` command that prints every `.metadata`/`.content` with record separators plus one line per `{uuid}/` directory (count of non-empty `.rm` files and a checksum of their names/sizes/mtimes = the annotation signature).
- **Web interface client**: `Invoke-RedriveWeb` drives `curl.exe` (ships with Windows 10 1803+; handles multipart, chunked and the tablet's dual `Content-Length` + `chunked` framing) with a `HttpWebRequest` fallback. Rules learned from a measured 3.27 device: always send `Connection: close`; decode bodies as UTF-8 regardless of the `ISO-8859-1` charset header; `/documents/{id}` for a non-folder id returns the **root** listing with 200, so verify every entry's `Parent`; both `VisibleName` and `VissibleName` appear. Endpoints: `GET /documents/`, `GET /documents/{uuid}`, `POST /upload` (multipart field `file`, 201 on success), `GET /download/{uuid}/pdf` (annotated PDF rendered by the tablet; `placeholder` is the pre-3.2x path and now returns 400, so try `pdf` then `placeholder`), `GET /download/{uuid}/rmdoc` (raw archive, works from 3.10, for backups).
- **Keep-alive stance**: nothing is kept alive. The watchdog probes every 10 s; every cycle is a short burst of independent connections; failures are retried next cycle. This is the only design that survives the tablet's sleep cycle.

### 2. Setup (`Install.cmd` → `src/Setup.ps1`, runs as the user; one optional admin phase)
1. Preflight: PowerShell 5.1; the Windows OpenSSH binaries at `C:\Windows\System32\OpenSSH\` (`ssh`, `scp`, `sftp`, `ssh-keygen`, `ssh-keyscan`) — always called by absolute path, because Git for Windows puts its own `ssh.exe` on PATH. Missing OpenSSH client → admin phase (`Add-WindowsCapability OpenSSH.Client`).
2. `Unblock-File` everything (mark-of-the-web), copy the code to `%LOCALAPPDATA%\redrive\app\`, create `logs\`, `state\`, `keys\`, the mirror folder, and default `config.json`; pick the drive letter (R, else M/T/Z).
3. Generate one RSA-4096 key without passphrase (`ssh-keygen -t rsa -b 4096 -N ""` through the native wrapper with a raw argument string — PowerShell 5.1 silently drops an empty `""` argument and ssh-keygen would then prompt and hang). RSA works with every Dropbear the tablets ship; the `+ssh-rsa` opt-ins below cover the 2019-era one on rM1/rM2. Lock the file so Windows OpenSSH accepts it: `icacls <key> /inheritance:r /grant:r "*<user SID>:F"`.
4. Write a private `ssh_config` **without BOM** (`Set-Content -Encoding UTF8` writes one and ssh then reports "Bad configuration option"): `Host remarkable`, `HostName 10.11.99.1`, `User root`, `IdentityFile` (forward slashes, quoted), `IdentitiesOnly yes`, `UserKnownHostsFile` (private), `StrictHostKeyChecking accept-new`, `ServerAliveInterval 5`, `ServerAliveCountMax 3`, `ConnectTimeout 5`, `HostKeyAlgorithms +ssh-rsa`, `PubkeyAcceptedKeyTypes +ssh-rsa` (old option name, accepted by OpenSSH 8.1 and 9.5 alike), `LogLevel ERROR`.
5. Wait for the tablet ("plug in the cable and make sure the tablet is awake"), then install the key with only `ssh.exe`, run **attached to the console** so Dropbear's password prompt is visible; the user pastes the password once (Settings → General → Help → About → Copyrights and licenses, "GPLv3 Compliance"); redrive never stores it:
   ```
   ssh.exe -F <cfg> -o PubkeyAuthentication=no -o PreferredAuthentications=password -o NumberOfPasswordPrompts=1 remarkable "mkdir -p /home/root/.ssh && chmod go-w /home/root && chmod 700 /home/root/.ssh && touch /home/root/.ssh/authorized_keys && chmod 600 /home/root/.ssh/authorized_keys && grep -qF '<keydata>' /home/root/.ssh/authorized_keys || echo 'ssh-rsa <keydata> redrive-<PC>' >> /home/root/.ssh/authorized_keys; grep -qF '<keydata>' /home/root/.ssh/authorized_keys && echo REDRIVE_KEY_OK"
   ```
   (`chmod go-w /home/root` matters: Dropbear refuses key auth when any directory from home down is group- or world-writable.) Success = `REDRIVE_KEY_OK` on stdout.
6. Verify key login (`ssh -o BatchMode=yes remarkable "echo REDRIVE_AUTH_OK"`), read firmware version (`IMG_VERSION` in `/etc/os-release` on 3.2x; `/usr/share/remarkable/update.conf` on older rM2 firmware; `/etc/version` build stamp), `uname -m`, free space, Dropbear version from the SSH banner, whether an `sftp-server` exists; record them in config for Doctor.
7. Make sure the USB web interface is on: read `WebInterfaceEnabled` from `/home/root/.config/remarkable/xochitl.conf`; if off, `systemctl stop xochitl` → set `WebInterfaceEnabled=true` under `[General]` → `systemctl start xochitl` (the conf is rewritten by xochitl on exit, so edit only while it is stopped). Wait for port 80.
8. Compile a 20-line console-less launcher with the in-box C# compiler (`Add-Type -OutputType WindowsApplication` → `bin\redrive-tray.exe`) that starts `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -STA -File …\redrive.ps1 tray` with `CreateNoWindow`; this is what avoids the console flash at logon without VBScript or `conhost --headless` (which EDR tools flag). Fallback if AppLocker blocks it: plain `-WindowStyle Hidden` with a brief flash.
9. Autostart: register a logon Scheduled Task from XML as the current user with `LogonType InteractiveToken`, `RunLevel LeastPrivilege`, `Delay PT20S` (taskbar must exist before the icon), `ExecutionTimeLimit PT0S` (the cmdlet default of 3 days would kill the tray), `MultipleInstancesPolicy IgnoreNew`, battery settings off. Whether a standard user may register this varies by policy; on AccessDenied fall back to a Startup-folder shortcut (visible in Task Manager → Startup apps).
10. `subst` the drive, run the first sync with console progress, start the tray, print "Done — look for the green dot near the clock".
11. Admin phase only when needed (`Start-Process powershell -Verb RunAs`, one UAC prompt): OpenSSH client capability, task registration if it failed, and the optional raw-mount stack via winget (`WinFsp.WinFsp`, `SSHFS-Win.SSHFS-Win` or `Rclone.Rclone`). The admin phase never creates drives: DOS device names are per logon session, so a `subst` or `net use` made by an elevated process is invisible to Explorer and OneNote. The CLI refuses `mount`/`tray` when elevated.

Host-key policy: the tablet regenerates its SSH host key on every firmware update (and on factory reset). Because the link is a direct USB cable, redrive keeps its own `known_hosts`, and on "REMOTE HOST IDENTIFICATION HAS CHANGED" it clears that file, logs "tablet host key changed (firmware update or reset?)", and reconnects; if the key login then fails too, the tablet was reset and Doctor says "run Setup again".

### 3. Mirror engine (`src/Mirror.ps1`, `src/Device.ps1`)
**Local layout** (`%USERPROFILE%\reMarkable`, shown as `R:`):
```
R:\<tablet folders, real names>\<Document title>.pdf   ← tablet-rendered PDF incl. handwriting; read-only attribute
R:\OneNote\<Notebook>\<Section>\<Page>.pdf            ← pushed by the bridge; mirrored like any other folder
R:\_Inbox\                                             ← anything dropped here goes to the tablet root
```
State: `%LOCALAPPDATA%\redrive\state.json` keyed by tablet UUID: name, parent, type, `lastModified`, local relative path, rendered-at timestamp, hasAnnotations, plus a map of local file hashes → UUID for files we pushed.

**Pull cycle** (runs on every connect and every `SyncIntervalMinutes` while connected):
1. Index: one SSH command dumps all `.metadata` + `.content` files (delimited text) plus `ls` of each `{uuid}/` directory to know which documents carry `.rm` stroke files. Parse to objects; skip `deleted:true` and `parent:"trash"`.
2. Build the virtual tree (parent chain → path), sanitize names for NTFS (illegal chars, trailing dots, reserved names, 200-char cap, duplicates get " (2)").
3. Diff against state: new or `lastModified` changed → re-render; parent/name changed → move/rename local file; gone or trashed → send the local file to the Recycle Bin.
4. Render changed documents with `GET /download/{uuid}/pdf` (then `placeholder` on older firmware) to a temp file, accept only `200` + `%PDF-` magic, then move into place and set read-only. EPUBs and native notebooks come back as PDFs too. One render at a time with `RenderPacingSeconds` between (bulk exports freeze the tablet). Bulk first run: newest first, progress in the tray tooltip. If the web interface is off, fall back to `scp` of the raw `{uuid}.pdf` and flag "annotations unavailable" in Doctor.

**Push cycle** (FileSystemWatcher + a scan each cycle):
1. Candidates: `.pdf`/`.epub` files under `R:\` that are not read-only mirror files, not temp (`~$`, `.tmp`, `.crdownload`), size stable for 2 s, and openable exclusively.
2. Upload via web interface `POST /upload` with `filename=<title without extension>` and `type=application/pdf` (on 3.27 the multipart filename becomes the title verbatim). xochitl ingests it immediately, no restart. Then re-list and identify the new entry by name and newest `ModifiedClient`; record its UUID.
3. Folder placement: measured 3.27 behaviour is that uploads **always land at root** (listing a folder first may still work on older firmware; `PushStrategy` covers both). Anything that must land in a folder is queued as a device op: `setParent <uuid> <folderUuid>`, plus `mkdir` ops for missing `CollectionType` folders. An experimental third strategy uploads an `.rmdoc` zip whose `.metadata` already carries `parent` (the tablet imports rmdoc live and takes the title from the archive; whether it honours `parent` is a field-test item — if yes, folders need no restart at all).
4. Fallback when the web interface is unavailable: `scp -O` the file plus synthesized `{uuid}.metadata` (modern shape: `createdTime`, `lastModified`, `lastOpened`, `lastOpenedPage`, `parent`, `pinned`, `type`, `visibleName`) and minimal `{uuid}.content` (`fileType`, `pageCount 0`, `pages []`, `transform`, `margins 125`) into `/home/root/redrive-staging/`; the device-ops window moves them into the xochitl directory while xochitl is stopped. Check for a `{uuid}.failure` file afterwards (seen on a real 3.27 device for hand-written metadata: document still usable, only excluded from cloud sync, which we do not use).
5. Record hash→UUID; the next pull replaces the local copy with the mirror (rendered, read-only) under the same name.

**Replace** (`Update-RedriveDocument -Uuid -Path`, used by the bridge). Default `ReplacePolicy = NewCopyRetireOld`: harvest annotations first if any; upload the new PDF as a **new** document; retire the old one (`RetireMode`: `Trash` → `parent:"trash"`, or `Archive` → move under `OneNote/_Archive` with a "(replaced <date>)" suffix, or `Keep`). Retirement is a metadata edit, so it rides the device-ops window. In-place overwrite of `{uuid}.pdf` is available as `ReplacePolicy = InPlace` but not default: ink is keyed to page ids and shifts when the page count changes.

**Device-ops window and restart policy.** reMarkable's own guidance is that xochitl must not be running while documents are changed, and Paper Pro's `xochitl.service` has `StartLimitBurst=4` per 10 minutes with `OnFailure=emergency.target` (the tablet reboots). So all metadata edits, folder creations, scp'd documents and retirements are batched into **one window per cycle**: `systemctl stop xochitl` → move staged files, apply `setParent`/`mkdir` edits with `sed`, bump `lastModified` → `systemctl start xochitl`. Preconditions: `AllowRestart`, at least 5 minutes since the last restart, fewer than 3 restarts in the last 10 minutes, the tablet idle (no `.rm` modified in the last 2 minutes), nothing in flight; the tray shows "reMarkable app restarting (~10 s)". Afterwards wait for `systemctl is-active`, port 22 and port 80, then verify the new UUIDs appear. If the window cannot run, ops stay queued (documents remain visible at root until then) and the report says so. Plain uploads and all renders never need the window, so a day with no folder moves needs no restart.

### 4. Drive letter (`src/Drive.ps1`)
- `subst R: %USERPROFILE%\reMarkable` at tray start (per-logon mapping; the tray app re-creates it each logon). Letter configurable; falls back to the next free letter and tells the user.
- Optional raw mount (`redrive mount-raw`, only when the tablet has an SFTP server): SSHFS-Win's `\\sshfs.kr\…` UNC form cannot take options or a custom key (it only uses `%USERPROFILE%\.ssh\id_rsa`), so run it directly as the user: `sshfs-win.exe cmd -f -o IdentityFile=/cygdrive/c/…/keys/id_redrive -o BatchMode=yes -o ServerAliveInterval=5 -o ServerAliveCountMax=3 -o reconnect -o HostKeyAlgorithms=+ssh-rsa -o PubkeyAcceptedKeyTypes=+ssh-rsa root@10.11.99.1:/home/root/.local/share/remarkable/xochitl S:` inside a Job Object that dies with the tray; **or** `rclone mount remarkable: S: --vfs-cache-mode writes --sftp-host-key-algorithms ssh-ed25519`. Health checks read the directory in a background runspace with a 3 s timeout, never on the UI thread. Documented as "for troubleshooting and backups; goes stale when the tablet sleeps".

### 5. Tray app and watchdog (`src/Tray.ps1`)
- WinForms `NotifyIcon` in a console-less STA PowerShell process (started by the compiled launcher); single instance via mutex `Local\redrive.tray` plus a pid file for `redrive tray -Stop`; a 1 s `System.Windows.Forms.Timer` drives a **pure** `Step-RedriveWatchdog` function (state + probe result + time → new state + actions), which is what the unit tests exercise.
- Icons are drawn in code (16×16 filled circle per state; handles built once and destroyed on exit) — no icon assets to ship. `NotifyIcon.Text` must stay under 64 characters.
- States: **Unplugged** (grey: no 10.11.99.x address), **Asleep** (yellow: address present, port closed; tooltip "Tap the tablet to wake it — R: shows the copy from 12:01"), **Syncing** (blue, with progress), **Up to date** (green), **Attention** (orange/red: repeated sync or auth failures, "open Doctor"), **Paused**. Loss is confirmed by a second failed probe 2 s later to avoid flapping.
- Cadence: after a loss, probe every 3 s for 2 minutes, then every 10 s; while connected, probe every 5 s and run the sync cycle every `SyncIntervalMinutes`; failures back off 5→10→20→40→60 s and flip to Attention after three in a row.
- Wake triggers: `NetworkChange.NetworkAddressChanged` and `SystemEvents.PowerModeChanged` are subscribed with `Register-ObjectEvent` and **drained inside the timer tick** with `Get-Event` (action blocks never run while the thread sits in `Application.Run`); a USB plug-in therefore probes within a second.
- Nothing in the tick may block more than ~2 s: sync work is chunked, or runs in a separate runspace polled by the tick.
- Menu: status line · Open drive (also double-click) · Sync now · Sync OneNote now · Pause syncing · Doctor (opens a visible console on purpose) · Show log · Settings (opens `config.json`) · Exit. Exit hides and disposes the icon, releases the mutex and stops any child process; it leaves the `subst` drive in place (the folder is still valid).
- Balloons only on transitions that matter ("Tablet connected — 3 pages sent, 2 notes received", "Sync problem — open Doctor"), never for the daily Asleep event, at most one per kind per 10 minutes, none in the first 20 s after logon.
- End-of-day nudge: if pushes are queued and the tablet has been asleep for more than `NudgeAfterMinutes`, one balloon: "3 pages waiting for the tablet — tap it to wake it". Never more than one nudge per hour.

### 6. Doctor (`src/Doctor.ps1`, `redrive doctor`)
Ordered checks (later ones skipped when a prerequisite failed), each with a one-line fix: PowerShell 5.1 and not elevated (elevated → "drives made here are invisible to Explorer") · Windows OpenSSH client present · config, key and key ACL correct · USB adapter present with a 10.11.99.x address (else: cable is charge-only or loose, tablet asleep, or the Device Manager driver fix) · ping and port 22 (else "tablet asleep or unplugged: tap it / re-plug the cable") · host key matches (else auto-reset and note "firmware updated or reset?"; `-ForgetHostKey`) · key login works (else "run Setup again") · SFTP subsystem present (informational) · firmware version read and changed since last time? · xochitl dir readable, entry count, free space · `WebInterfaceEnabled=true` and port 80 answers (else offer to enable it) · xochitl restart budget not exhausted · mirror folder, drive letter (`QueryDosDevice`) and a directory read of `R:\` with a 3 s timeout · index age vs last successful sync · OneNote running and COM answers (else "open OneNote") · tray running and autostart registered · interference hints as warnings: `Find-NetRoute` to 10.11.99.1 not on the USB interface ("VPN is capturing the tablet network — add a split-tunnel exception or disconnect"), third-party firewall products from Security Center · last sync time and last error from the log. Output as a console table with PASS/FAIL/WARN and the fix under each failure; `-Report` writes `logs\doctor-<timestamp>.txt` (versions, config, last 100 log lines) and copies it to the clipboard: "paste it into an email to your helper".

### 7. OneNote bridge (`src/OneNote.ps1`)
Facts we rely on (researched 2026-09-01): OneNote desktop COM works on Microsoft 365 Click-to-Run (x64 Office registers the CLSID in both registry views); OneNote for Windows 10 (UWP) has no COM and is retired; creating `OneNote.Application` launches ONENOTE.EXE if needed (out-of-process server), but `Publish()` is only reliable with OneNote genuinely open, so the bridge starts OneNote normally first if it is not running; the caller must be the interactive user at the **same elevation** (never SYSTEM, never elevated; an elevation mismatch shows as `0x80080005`); COM events are unavailable to managed code, so we poll; `Publish()` requires the target file not to exist (`0x8004201A`); "Insert File Printout" is unreliable in current builds, so we insert images we render ourselves; `UpdatePageContent` bumps `lastModifiedTime` on the page. The bridge runs as a separate hidden `-STA` worker process started by the tray (own COM lifetime, correct bitness, `Global\redrive-onenote-sync` mutex), with every COM call wrapped in a retry for `RPC_E_CALL_REJECTED`/`RETRYLATER` and an abort on `hrAppInModalUI` (`0x80042030`, "a dialog is open in OneNote").

**Export → tablet** (every `OneNote.PollMinutes`, default 5, while connected; also "Sync OneNote now"):
1. `GetHierarchy("", hsPages=4, [ref]$xml, xs2013=2)`; walk Notebook → SectionGroup → Section → Page; skip `isInRecycleBin`, locked/encrypted sections, and anything in the config exclude list (`OneNote.Include`/`Exclude` by notebook or section name; default: all notebooks).
2. Per page: compare `lastModifiedTime` with `onenote-state.json`; changed or new → `Publish($pageId, $tmpPdf, 3, "")` (delete stale temp first; retry once; catch and log `0x80042030` modal dialog, `0x8004201d` not synced, `0x80042031` sensitivity label, DLP failures).
3. Push to `OneNote/<Notebook>/<Section>/<Page>.pdf` through the mirror engine: new page → upload; existing page → `Update-RedriveDocument` (harvest first, then new copy + retire old). Renamed/moved page → same path (the new copy carries the new name/folder; the old one is retired). Deleted page → harvest any un-harvested ink into "From reMarkable", then retire the tablet copy. All retirements and folder moves ride the device-ops window.
4. Store exported `lastModifiedTime`, PDF hash, tablet UUID.

**Harvest → OneNote** (start of each cycle, so the morning plug-in brings the night's work in first):
1. From the index: documents under `OneNote/…` whose `lastModified` is newer than the push time and that have `.rm` files → candidate. Native notebooks anywhere else with changes → candidate for "From reMarkable".
2. Fetch the tablet-rendered PDF (already done by the pull cycle: reuse `R:\…pdf`). Rasterize with `Windows.Data.Pdf.PdfDocument` at ~150 dpi to PNG per page (WinRT from PowerShell 5.1, verified loadable here).
3. Append to the source page: `GetPageContent(pageId, [ref]xml, piBasic=0, xs2013=2)` to find the lowest existing page-level object (max `Position.y + Size.height`); if a previous redrive outline exists (its `objectID` is stored in state and in `one:Meta redrive.harvestOutlineId`), remove it with `DeletePageContent` so harvests replace rather than stack; then `UpdatePageContent` with a `<one:Page ID=…>` containing **only** `one:Meta` upserts (`redrive.docUuid`, `redrive.harvestHash`) and one new `<one:Outline>` (no `objectID`) positioned below, holding a small grey caption OE ("redrive harvest 2026-09-01 18:42 — 2 annotated page(s) of 3"), one `<one:Image format="png"><one:Size width height isSetByUser="true"/><one:Data>base64</one:Data></one:Image>` per **annotated** page only (page mapping from `.content` `cPages` order vs non-empty `.rm` files; all pages if unknown), and `<one:InsertedFile pathSource="…pdf" preferredName="… (annotated).pdf"/>`. Appends are chunked at 10 images per call. Harvest hash = SHA-256 of the sorted `pageId:rmSize:rmMtime` lines; equal hash → nothing appended.
4. Because the page has now changed, the **next export cycle re-publishes it with the handwriting baked in and refreshes the tablet copy** (whose strokes were just harvested). That is the intended daily flattening; document it plainly. Since the harvest outline is replaced, not stacked, the page always shows the latest full render of its annotated pages, which already contains earlier handwriting.
5. Native tablet notebooks (`fileType: notebook`, or anything under a configurable inbox folder): one OneNote page per notebook in `<From reMarkable notebook>/<section>` (section created via `OpenHierarchy(…, cftSection=3)` if missing; page via `CreateNewPage` + a `one:Title`), owned via `one:Meta redrive.docUuid` and recoverable with `FindMeta` if the state file is lost; the harvest outline is replaced when the notebook changes. Pages in read-only sections cannot be updated, so their harvests are routed here too.
Tip for docs: set View → Paper Size to Letter/A4 in OneNote for pages that will be read on the tablet; auto-sized pages export as odd PDF pages.

### 8. Fake tablet harness (`harness/`)
Docker container (Docker Desktop; WSL Debian as fallback with the same entrypoint) built to match the tablet's real quirks, not just its shape:
- **Debian slim + Dropbear** (not OpenSSH): no SFTP server, so `scp` without `-O` fails here exactly as on the tablet; root login by key (mounted `authorized_keys`) and by password `fake` for the Setup path; host keys persisted in a volume. Root's login shell is a wrapper that puts static BusyBox first on `PATH`, so any GNU-only flag in a remote command fails in the harness before it fails on the tablet. Loopback alias `10.11.99.1/32` so the container answers on the tablet's real address inside itself.
- **`systemctl` shim** modelling only xochitl: `stop`/`start`/`restart`/`is-active`/`status`, an 8 s restart gap during which the mock web UI is down, and the real start-rate limit (5th start within 10 minutes fails with systemd's "start of the service was attempted too often").
- **`gen-sample-xochitl.py`** (stdlib only): folders `Work` and nested `Work/Projects`; a 3-page PDF with two annotated pages (real v6 `.rm` fixtures borrowed from rmscene's MIT test data, plus a zero-byte `.rm` placeholder as 3.x writes them) and a formatVersion-2 `cPages` `.content`; an EPUB; a native 2-page notebook; a trashed document (`parent:"trash"`); a document titled `Résumé — 日本語 ✓`; system files per profile (`paperpro-3.27`: `/etc/os-release` with `IMG_VERSION`; `rm2-3.11`: `update.conf`), and `xochitl.conf` with `WebInterfaceEnabled=true`. `.metadata` uses the modern 3.x shape with millisecond-epoch strings.
- **`mock-webui.py`** (`http.server`): `/documents/` and `/documents/{id}` (folder listing; non-folder id → root listing, as measured), `POST /upload` (201, create-only at root, filename verbatim; flags `FAKE_UPLOAD_USES_LAST_FOLDER`, `FAKE_STRIP_EXT`, `FAKE_RMDOC_HONORS_PARENT` to model the other firmware beliefs), `/download/{id}/pdf` (stored PDF or a generated stand-in for notebooks/EPUBs), `/download/{id}/placeholder` (400 unless `FAKE_LEGACY_PLACEHOLDER=1`), `/download/{id}/rmdoc` (zip), `/thumbnail/{id}`, `/log.txt`; `charset=ISO-8859-1` header on UTF-8 bodies, `Connection: close`, optional dual framing; catalog reloaded only on (re)start when `FAKE_LIVE_SCAN=0`, so scp'd files stay invisible until `systemctl restart xochitl`.
- Ports 2222 (ssh) and 8080 (web); `Start-FakeTablet.ps1` builds, waits for port 2222 and writes `config.fake.json` (`Host 127.0.0.1`, `SshPort 2222`, `WebBase http://127.0.0.1:8080`, `ScpLegacyProtocol true`) selected via `-Profile fake` or `$env:REDRIVE_CONFIG`; `Reset-FakeTablet.ps1` regenerates data.
- Known fidelity gaps: no sleep (use `docker pause` in tests), restart has no side effects on files, renders contain no ink, no USB adapter on the Windows side, Debian's Dropbear is newer than rM2's 2019.78.

### Field-test checklist (`docs/FIELD-TEST.md`, run on the first real tablet, ~45 min; every result recorded in a table)
1. Plug in; `Get-NetAdapter` shows the tablet's USB Ethernet adapter and Windows has 10.11.99.2; `Test-NetConnection 10.11.99.1 -Port 22`.

4. `scp -O` a file to `/home/root/` (expect OK) and `scp` without `-O` (record the exact failure text, if any).

7. Upload a hand-built `.rmdoc` (metadata with `parent` = folder uuid): does it honour the folder, title and `fileType`?
8. `scp -O` a PDF + synthesized `.metadata`/`.content` into the xochitl dir with xochitl running: invisible? Then a device-ops window (stop → files → start) with `reset-failed` first; time until the UI is back; two minutes later check for `{uuid}.failure` and whether `.content` was rewritten.
9. 11. Let the tablet sleep plugged in; poll `ssh -o ConnectTimeout=5 remarkable date` every 30 s and log the first failure; tap it; log when it answers again and whether Windows re-enumerates the adapter; record the Battery settings.
12. Full OneNote loop overnight: pages exported → visible on the tablet in their folders → annotate → next morning the images appear on the pages and the tablet copies are refreshed.

## Risks and mitigations
- **Unverified device behaviour** (upload folder semantics, rmdoc `parent`, `.content` shape, render speed, sleep): every such point is a strategy flag in config with a safe fallback, and is on the field-test list.
- **OneNote quirks**: modal dialogs block COM (retry later, tell the user), locked sections and sensitivity labels cannot export (skip + report), DLP may block `Publish` (report), auto-sized pages export oddly (doc tip).
- **Corporate lockdown**: AppLocker/Constrained Language can block scripts and COM; SmartScreen flags downloaded zips (Setup unblocks files; docs explain). If this bites, the compiled rewrite is the answer.
- **Data safety**: Windows-side deletes never delete on the tablet in v1; replaced pages are harvested first; the raw mount is opt-in; `/download/{uuid}/rmdoc` backup verb available.
- **Folder filing needs restarts on 3.27** because web uploads land at root: the device-ops window is idle-gated and budgeted, documents sit at root until it runs, and the report says so. If the `.rmdoc` upload honours `parent` in the field test, restarts disappear from the normal day.
- **Harvest images repeat the page's own text** (the tablet renders the whole page, not just the ink layer). Acceptable for v1 and stated in the docs; an ink-only layer would need a local `.rm` renderer (later, optional).
- **Bulk first sync** on a full tablet takes minutes (renders are seconds each): newest first, visible progress, resumable.
- **Name collisions / long paths / Unicode**: sanitizer + dedupe + `\\?\` prefix where needed; tests cover it.
